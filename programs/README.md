# 로봇 프로그램

실제 로봇 프로그램처럼 **보기 → 판단 → 움직이기** 세 단계로 나눈 프로그램들입니다. 로봇은 시뮬레이션의 정답 위치를 모르고 **카메라 사진만** 봅니다. 정답은 채점에만 씁니다.

| 프로그램 | 하는 일 | 결과 (2026-09-27) |
|---|---|---|
| `sort_by_color.py` | 위 카메라로 빨강·파랑·초록 큐브를 찾아 색깔별 칸에 옮김 | 무작위 배치 10번, 큐브 30개 중 **30개** 제자리 · 인식 30/30 (오차 약 0.1cm) |

```bash
python programs/sort_by_color.py            # 한 번
python programs/sort_by_color.py --trials 10 # 무작위 배치로 정확도 측정
python programs/sort_by_color.py --view      # 실시간 3D 창
```

## 구조

| 단계 | 파일 | 내용 |
|---|---|---|
| 보기 | `perception.py` | 사진 → 색 판정(채널 우세 방식) → 연결 영역 → 핀홀 카메라 모델로 작업대 좌표 |
| 판단 | `sort_by_color.py` | 색 → 칸 대응표, 순서 정하기 |
| 움직이기 | `sim/robot.py` | `move_to`(역기구학·속도 제한), `grip`, `move_joints`(카메라를 가리지 않는 자세) |

## 만들면서 부딪힌 것 (실제 로봇에도 똑같이 생기는 문제)
1. **팔이 카메라를 가린다** — 처음 자세에서 팔이 파란 큐브를 덮음 → 팔을 받침 쪽으로 접는 「보는 자세」를 따로 둠
2. **조명이 색을 바꾼다** — 초록 큐브가 (81, 255, 147)로 찍혀 고정 기준에서 놓침 → 「한 채널이 얼마나 센가」로 판정 (인식 오차 0.7cm → 0.1cm)
3. **빨리 돌면 물건이 빠진다** — 오른쪽 끝에서 왼쪽 칸으로 크게 돌 때 큐브가 날아감(12/15) → 관절 속도 상한 0.8 rad/s (30/30)

## 실물 로봇으로 옮길 때 (미확인 — 하드웨어로 시험하지 않음)
- 카메라: `camera_image()` 자리에 USB 카메라 사진. `TopCamera`의 위치·화각을 실측하거나, 작업대 네 모서리를 찍어 보정
- 로봇: `move_to`·`grip`·`move_joints` 세 함수만 실물 드라이버로 바꾸면 프로그램은 그대로. SO-ARM100/101은 오픈소스 LeRobot 라이브러리로 서보를 움직이는 방식이 알려져 있음 — 관절 이름·범위 대응은 실물 확인 필요
- 속도 제한·작업 공간 제한은 실물에서 더 중요(사람 손, 케이블)
